# สร้างออเดอร์และตรวจพื้นที่บริการตามถนน

`POST /orders` ตรวจระยะทางก่อนสร้างออเดอร์ โดย frontend ใช้ `/api/orders` ผ่าน proxy ตามเดิม ไม่ต้องเพิ่มพิกัดใน body

## ลำดับการทำงาน

1. ตรวจจำนวนกล่อง 1–3 กล่อง และ `customer_id` เป็นจำนวนเต็มบวก
2. อ่านที่อยู่และพิกัดลูกค้าจากตาราง `customers` ไม่ใช้พิกัดที่ client ส่งมา
3. ใช้พิกัดร้านใน [service/shop.ts](../service/shop.ts): `16.246063, 103.252125` ซึ่งตรงกับพิกัดร้านที่ UI ใช้อยู่
4. เรียก `getRoadDistances()` เพื่อขอระยะทางจากร้านไปหาลูกค้าผ่าน OSRM Table โปรไฟล์ `driving`
5. สร้างออเดอร์ได้เมื่อระยะทางไม่เกิน 3 กม. รวมกรณีเท่ากับ 3 กม. พอดี โดยเทียบก่อนปัดเศษ
6. คัดลอกที่อยู่และพิกัดลง `orders.delivery_*` ด้วย `INSERT ... SELECT` เฉพาะเมื่อข้อมูลจุดส่งยังตรงกับที่ตรวจไว้ หากมีการเปลี่ยนระหว่างรอ OSRM จะไม่บันทึกพิกัดใหม่ที่ยังไม่ผ่านการตรวจ

ระยะเป็นระยะตามถนนที่ OSRM เลือก ไม่ใช่เส้นตรง และไม่รับประกันว่าเป็นเส้นทางระยะสั้นที่สุด ไม่ใช้เส้นตรงแทนเมื่อ OSRM ล้มเหลว

## ผลตอบกลับ

| HTTP | ความหมาย |
|---|---|
| 201 | สร้างสำเร็จ ได้ `affected_row` และ `last_idx` เหมือนเดิม |
| 400 | จำนวนกล่องหรือรหัสลูกค้าไม่ถูกต้อง |
| 404 | ไม่พบลูกค้า หรือถูกลบระหว่างตรวจระยะทาง |
| 409 | ที่อยู่หรือพิกัดลูกค้าเปลี่ยนระหว่างตรวจ ให้ลองสร้างใหม่ |
| 422 | พิกัดลูกค้าไม่ถูกต้อง ไม่มีเส้นทาง หรือระยะเกิน 3 กม. |
| 502 | ติดต่อ OSRM ไม่สำเร็จหรือคำตอบไม่ถูกต้อง ยังไม่สร้างออเดอร์ |
| 500 | ฐานข้อมูลหรือการทำงานภายในผิดพลาด |

ตัวอย่างเมื่อลูกค้าอยู่นอกพื้นที่:

```json
{
  "error": "ลูกค้าอยู่นอกพื้นที่บริการ 3 กม. ตามถนนจากร้าน",
  "distance_km": 3.25
}
```

## จำลองออเดอร์: POST /orders/simulated

- เปลี่ยน: อ่านลูกค้าทั้งหมด ตัดพิกัดที่ผิดออก แล้วขอระยะทางตามถนนจากร้านด้วย `getRoadDistances()` ก่อนสุ่ม
- สุ่มเฉพาะลูกค้าที่มีเส้นทางและระยะไม่เกิน 3 กม. รวมกรณีเท่ากับ 3 กม. พอดี
- ยังคงสร้าง 20–30 ออเดอร์ จำนวน 1–3 กล่องต่อออเดอร์ ขาย 65 ต้นทุน 40 บาท วันที่ไทยปัจจุบัน และเก็บสำเนาที่อยู่/พิกัดที่ผ่านการตรวจในออเดอร์
- สุ่มลูกค้าซ้ำได้เช่นเดิม ไม่จำเป็นต้องมีลูกค้าครบ 20 คน
- ใช้พิกัดร้านเดียวกับ `POST /orders` ไม่รับพิกัดร้านจาก body
- ถ้าไม่มีลูกค้าที่ใช้ได้ ตอบ `422` โดยไม่สร้างออเดอร์; ถ้า OSRM ล้มเหลว ตอบ `502` โดยไม่สร้างออเดอร์
- คืน `affected_row` และ `last_idx` แบบเดิม เมื่อสร้างสำเร็จ

## ขอบเขต

- ทั้ง `POST /orders` และ `POST /orders/simulated` ตรวจพื้นที่บริการตามถนนก่อนสร้างออเดอร์แล้ว
- ออเดอร์เก่ายังคงตำแหน่งเดิม ไม่แก้หรือย้ายข้อมูลย้อนหลัง
- ใช้เกณฑ์ `SERVICE_AREA_KM` ร่วมกับตัวคำนวณแผน และยังเก็บ `validateServiceArea()` ไว้ตรวจซ้ำตอน preview
- `settings.origin` ใน API preview ยังรับค่าจากผู้เรียก; ถ้าปรับพิกัดร้านใน frontend/test-api ต้องให้ตรงกับพิกัดร้านที่ใช้ตรวจสร้างออเดอร์ด้วย

ทดสอบด้วยฐานข้อมูลและ OSRM จำลอง ไม่แก้ข้อมูลจริง:

```sh
npm test -- test/order-location.test.ts test/order-nearby.test.ts test/delivery-planning.test.ts test/job-sheet.test.ts
npm run typecheck
```
