# ค้นหาออเดอร์ใกล้เคียงตามระยะทางถนน

`GET /orders/nearby?lat=13.7563&lng=100.5018`

- `lat` และ `lng` คือพิกัดละติจูดและลองจิจูดของจุดเริ่มต้น
- ส่งข้อมูลออเดอร์และลูกค้าในรูปแบบเดิม พร้อมฟิลด์ `distance_km` โดยเรียงระยะทางจากน้อยไปมาก
- เปลี่ยน: ที่อยู่และพิกัดมาจาก `orders.delivery_*` ที่คัดลอกตอนสร้างออเดอร์ โดยยังส่งชื่อฟิลด์ `address`, `latitude`, `longitude` เหมือนเดิม การแก้พิกัดลูกค้าไม่ย้ายจุดส่งของออเดอร์เก่า
- แสดงเฉพาะออเดอร์ที่มี **ระยะทางตามถนนไม่เกิน 3 กม.** ตามเกณฑ์ปัจจุบันของ `/orders/nearby`
- ใช้ OSRM Table โปรไฟล์ `driving` คำนวณระยะทางตามเส้นทางรถยนต์ที่ระบบเลือก เส้นทางนี้ไม่จำเป็นต้องมีระยะสั้นที่สุด
- ไม่แสดงออเดอร์ที่ไม่มีพิกัดปลายทาง พิกัดไม่ถูกต้อง หรือไม่สามารถหาเส้นทางไปถึงได้
- หากไม่พบออเดอร์จะส่ง `[]` กลับมา หาก OSRM ทำงานล้มเหลวจะตอบสถานะ `502` พิกัดต้นทางไม่ถูกต้องจะตอบ `400` และฐานข้อมูลทำงานล้มเหลวจะตอบ `500`
- API นี้ส่งระยะทางกลับมา แต่ยังไม่ได้ส่งข้อมูลเส้นทางสำหรับวาดเส้นบนแผนที่ ส่วน `/customers/nearby` ยังทำงานเหมือนเดิม

ค่าเริ่มต้นเรียก `https://router.project-osrm.org` โดยไม่ต้องติดตั้ง OSRM หรือใช้ API key หากมีเซิร์ฟเวอร์ OSRM ของตนเอง ให้ตั้งค่าใน `.env` แล้วรีสตาร์ต Backend:

```dotenv
OSRM_BASE_URL=https://your-osrm-server.example
```

หากหลายออเดอร์ใช้พิกัดลูกค้าเดียวกัน ระบบจะขอระยะทางของพิกัดนั้นเพียงครั้งเดียวแล้วใช้กับทุกออเดอร์ที่เกี่ยวข้อง แบ่งคำขอเป็นชุดไม่เกิน 99 ปลายทาง รวมต้นทางเป็น 100 จุดต่อคำขอ

คำขอไปเซิร์ฟเวอร์เดโมเข้าคิวทีละรายการในโปรเซสเดียวกัน เว้นระยะอย่างน้อย 1.1 วินาที และรอคำตอบสูงสุด 10 วินาทีต่อคำขอ ไม่ใช้ระยะทางตรงแทนเมื่อ API ล้มเหลว
หากรัน Backend หลายโปรเซส ต้องจัดการคิวร่วมกันหรือใช้เซิร์ฟเวอร์ OSRM ของตนเอง

- [เอกสาร OSRM API](https://project-osrm.org/docs/v5.24.0/api/)
- [ข้อมูลเซิร์ฟเวอร์เดโม OSRM](https://github.com/Project-OSRM/osrm-backend/wiki/Demo-server)

คำสั่งรันชุดทดสอบเฉพาะส่วนนี้ โดยจำลองฐานข้อมูลและบริการเส้นทาง จึงไม่แก้ไขข้อมูลจริง:

```sh
npm test -- test/order-nearby.test.ts
```
